- **UI/aksesibilitas/responsif**: di luar cakupan permintaan (backend diprioritaskan).
- **`ml/`**: tidak dipakai runtime aplikasi.
- **Konfigurasi produksi** (`TRUSTED_PROXIES`, `CORS_ORIGINS`, TLS): tidak ada di repo.
- **Distribusi serangan lintas IP**: hanya dianalisis dari kode, tidak disimulasikan.

  masih menyetel `usesCleartextTraffic="true"`, jadi build debug tetap boleh HTTP.

### Audit pass 6 (2026-10-30) — tester review: menutup lubang mutasi

Enam celah test ditutup. Tiap penutup dibuktikan dengan mutasi: test harus gagal
saat perilakunya dirusak. Lima mutasi dijalankan, kelimanya tertangkap (`exit=1`):

| Mutasi | Test penangkap |
|---|---|
| `ORDER BY (operation_key=?) DESC` diubah `ASC` | `stock-sync` "canonical receipt wins over a case-variant decoy" |
| `lower(operation_key)=?` diubah `upper(?)` | `stock-sync` "upper-case legacy receipt replays" |
| `CREATE INDEX` migrasi 0012 dikomentari | `sync-migration` "0012 builds the canonical-key index" |
| `keptExisting` dikembalikan `[]` | `seed.test.js` idempotensi |
| guard remote diganti `const remote = false` | `seed-cli-guard` (unit + spawn) |

Perubahan test:
- `nursery.test.js`: test lama yang menegaskan "tanpa kunci = 201" dihapus; bertentangan dengan kontrak dan hanya hijau karena shim fixture.
- `stock-sync.test.js`: tambah jalur replay receipt huruf besar (200, `replayed`, id sama, tanpa baris stok baru) dan kasus dua baris beda kapitalisasi dengan receipt palsu.
- `sync-migration.test.js`: apply 0012 pada DB berisi dua receipt beda kapitalisasi, assert indeks ada; rollback, assert indeks hilang.
- `seed.test.js`: `keptExisting` diassert kosong pada seed pertama, berisi dua username pada re-seed.
- `seed-cli-guard.test.js` (baru): tabel `isRemoteUrl` (termasuk `LIBSQL://`, `https:/broken`, `null`) dan spawn CLI dengan DB remote tanpa opt-in, harap exit 1 sebelum koneksi.
- `sync-contract.test.js`: tambah assert jumlah baris `jenis_inventaris` dan `meja_tanam` = 0, jadi klaim "tidak ada tulisan" benar untuk 7 dari 7.

Keputusan untuk dua sisa temuan:

- **Meta-test diperkuat, tetap tripwire.** Daftar wrapper kini diturunkan dari
  filesystem (setiap `features/*/write.ts`), pemindaian call-site rekursif, dan
  komentar menyatakan batasnya: bukti perilaku ada di test per-fitur. Dua mutasi
  membuktikan jaringannya: menambah `write.ts` tanpa helper, dan menaruh
  `authenticatedWrite(` di subfolder, keduanya gagal (`exit=1`).
- **`x-client-id` di `POST /stok/:id/reverse`: dokumen yang diperbaiki, bukan kode.**
  Reverse membuat baris ledger baru, jadi memesan `client_id` di sana sah. Mengubah
  kode akan mencabut kemampuan dan mematahkan test yang memang menetapkannya, tanpa
  menambah keamanan. Kalimat dokumen sekarang: header dipakai untuk operasi yang
  membuat catatan baru (create, termasuk reverse), dan diabaikan saat mengubah.
